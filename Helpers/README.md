# Display helpers

These files are a minimal, local snapshot of the supplied
`2026-10-28-显示器控制台源码` archive and `~/Library/Scripts/builtin_brightness.c`.
The archive directory date is a label, not an upstream commit or a guarantee
that its sources match every later installed binary. The original app is not
used as a build input and is never modified by the packaging script.

## Source and link dependencies

| Output | Sources | Frameworks |
| --- | --- | --- |
| `DDCControl` | `DDCControl.m`, `m1ddc-vendor/sources/ioregistry.m`, the three vendor headers | Foundation, IOKit, ApplicationServices, CoreDisplay |
| `DisplayManager` | `DisplayManager.swift` | AppKit, CoreGraphics, Foundation and system Swift libraries; SkyLight loaded at runtime |
| `ScreenBlank` | `ScreenBlank.m` | Cocoa, ApplicationServices, Carbon; CoreBrightness, DisplayServices and SkyLight loaded at runtime |
| `builtin_brightness` | `builtin_brightness.c` | ApplicationServices, CoreGraphics, private DisplayServices |

Only the m1ddc transport-discovery source and required headers are vendored.
`DDCControl` implements its own checked exchange, so m1ddc's standalone CLI
and `i2c.m` are not needed. Preserve the local transport changes, including
MCDP29xx detection and the DDC chip-address selection. This is a local modified
snapshot of waydabber/m1ddc, with its complete MIT license in
`m1ddc-vendor/LICENSE`; it is not asserted to match an upstream release.

The initial 3.0.0 snapshot changed sibling executable lookup:
`DisplayManager` finds `builtin_brightness` and its rollback child in its own
executable directory; `ScreenBlank` does the same for `DisplayManager` and
`DDCControl`. DDC allowlists/readback, screen-availability checks, the saved
layout/rollback protocol, brightness snapshots, recovery shortcuts/signals,
state file names and locks initially retained their original behavior.

The 3.0.1 safety patch cancels stale blanking work, restores owned state on
external removal before further dimming, retains failed restoration state,
and defers recovery for closed lids and actual system sleep. Ordinary topology
callbacks never re-darken the builtin display. DisplayManager rechecks external
availability before and after disabling the builtin, records recovery ownership,
and allows a finite recovery burst for delayed/empty topology. Brightness-zero
writes require a usable external both before and after the operation and record
recovery ownership. See ../DISPLAY_SAFETY_FIX.md for the installation boundary.

The old `PomodoroTimer` is not needed and is not bundled. No launch agent, auto-brightness daemon,
`display-wake-listener` or legacy UI executable is bundled. The main app's
native `AutoBrightnessController` samples the system's `CurrentLux` every
45 seconds and invokes the bundled `DDCControl`. It requires a valid exposed
CurrentLux sensor and a supported display/connection; no legacy als script
or Homebrew installation is required. The legacy `paused_until` and
`last_target` files remain compatible. Main-app lifecycle manages polling
and recovery, separately from these helper processes.

## Build and safe verification

The application must use an app-aware resource accessor, as generated by
SwiftPM's Xcode build system. The packager rejects the known CLI accessor
that only searches the app root and build directory.

From the project root, use `Scripts/package-app.sh --skip-build` to compile
helpers without invoking SwiftPM. Pass `--binary` if the main executable is
outside `.build/release`. See the main README for resource bundle selection,
output directory and prebuilt-helper options. The helper deployment target is
macOS 14.0 arm64; no Intel DDC support is claimed.

The packaging script never executes a helper. For explicit policy checks,
the following existing entry points do not set brightness, change layouts,
or power off screens:

```bash
'dist/Super Dashboard.app/Contents/MacOS/DisplayManager' --self-test
'dist/Super Dashboard.app/Contents/MacOS/ScreenBlank' --self-test
```

Expected results: DisplayManager has 6 availability checks and 4 recorded
transition scenarios; ScreenBlank has 22 recovery scenarios. Both entry points
also accept --safety-regression. ScreenBlank selects fake display metadata,
brightness functions, commands and delayed blocks before initializing any
private framework or touching live state; temporary test state is isolated.
Do not run ScreenBlank with
no arguments to inspect it: the default operation is hardware screen-off.
DDCControl and builtin_brightness have no pure self-test entry point.

Hardware restrictions and the main app's read-only self-check and page
capture commands are documented in the main README. The final app build,
packaging, self-check and screenshots are performed by the main agent.
Helper tests exercise the real transition/recovery functions with injected
effects. They do not verify private API behavior or physical disconnection.

## Notices shipped in the app

The packager includes the m1ddc MIT license, the project-level notices, and
the existing resource bundle notices/licenses. `Licenses/LGPL-2.1.txt` adds
the LGPL 2.1 text missing from the mobile-device resources' GPL-2.0 COPYING
file. `Licenses/OpenSSL-Apache-2.0.txt` contains the Apache 2.0 license shipped
with OpenSSL 3. These license texts were taken from the locally installed
GLib and OpenSSL distributions; those installations are not build inputs.
Exact source revisions/build recipes for the pre-existing mobile-device
binaries and the companion-device example were not supplied by this helper
snapshot; the packager does not manufacture that provenance.
